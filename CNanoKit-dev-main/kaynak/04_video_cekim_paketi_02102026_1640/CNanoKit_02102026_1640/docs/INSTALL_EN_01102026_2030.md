# CNanoKit 0.9 — Installation and User Guide (English)

Use the **PIC18F56Q71 Curiosity Nano** with the **Positron8** compiler: compile, program, and talk to your program over USB.

- Any **one** of three IDEs is enough: **Positron Studio**, **Proton IDE**, or **VS Code + Positron extension**.
- You need no MPLAB X IDE / IPE and **no wires** on the kit.
- Free, no warranty, no support obligation. okmn, 2026.
- Türkçe: `KURULUM_TR_01102026_2030.md`

> **⚠ Not yet verified.** The package was tested on Windows 11 **Pro** with MPLAB X installed. Two cases are not tested yet:
> 1. Installing on **Windows 11 Home**.
> 2. The kit's COM port appearing by itself on a **clean Windows with no MPLAB X ever installed**.
>
> Section 7 gives the expected result and the evidence for it. If you try either case, please share the result.

## 0. Read this first — the 6 most common questions

| Question | Short answer |
|---|---|
| Do I need Jon Walker's (JonW) FREELOADER files or his Positron code? | **No.** Compiling, programming and the monitor need none of JonW's files. The kit's on-board debugger (nEDBG) does the programming. |
| Do I have to fit wires on the kit? | **No.** Normal use is one USB cable, nothing else. The wires are only for trying JonW's bootloader (section 9). |
| Must I add a bootloader to my own code? | **No.** The kit has its own programmer. A bootloader is useful later for **your own board** that has no programmer (section 9). |
| Do I need MPLAB X? | **No.** It is only a fallback, for its driver, if the kit's COM port never appears (section 7). |
| Do I need all three IDEs? | **No.** One is enough. |
| Which of my UART pins are used? | The kit's USB-serial line is on **UART2: RB4 = TX, RB5 = RX**. If you don't use the monitor, those pins are yours too. UART1 and all other pins are completely yours. |

## 1. What is in the package

| File | What it does | What it is not |
|---|---|---|
| `CNanoProg_Setup.bat` + `CNanoProg_Setup.ps1` | **Setup.** Run once, and once again after a new Windows install. It installs what is needed and adds settings lines to the IDEs. Running it again is harmless. | Not a program for daily use. |
| `CNanoProg.exe` + `CNanoProg.ps1` | **Programmer**, called by the IDEs. It checks the hex file and the PIC on the kit, then writes, verifies and resets. | Not a compiler; Positron compiles. |
| `CNanoMonitor.exe` + `CNanoMonitor.ps1` | **CNano Monitor:** a TR/EN serial monitor for the kit's USB COM port. Text and HEX view; text and HEX send. | Not a breakpoint debugger. |
| `CNanoProtonPlugin.exe` | **Proton IDE plugin**: the small program behind the "Program (CNanoProg)" and "Monitor (CNanoMonitor)" buttons. | Does not run on its own; double-clicked, it explains how to use it. |
| `examples\CNANO_HELLO_56Q71.bas` | First program. It prints "Hello/Merhaba", echoes what you type, reports SW0 presses and blinks LED0. | — |
| `examples\CNANO_HELLO_56Q71_NOLED.bas` | The same program with the LED off. Use it when a wire is fitted on RC7. | — |
| `examples\CNANO_KOMUT_56Q71.bas` | **Command test:** the PIC waits quietly. `okmn` (text) → LED tick ×4 + 300 ms; HEX `53` → LED PWM fade (500+500 ms); `come` → a DATA line every 250 ms. Each runs **until `stop`**; a new command replaces the running one. `help` = list. Optional external LED: RD0 (left row hole 16) → 1 kΩ → LED → GND. | Works with or without wires: at the first command it detects the RB5–RC7 wire; if fitted it never drives the LED and shows it on the monitor as text/bar. |
| `docs\` | This guide, the Turkish guide and the wiring pictures. | — |
| `LICENSE.txt` | Licence. | — |
| `log\`, `settings.ini` | Created on the first run: logs, settings backups, language/port/baud. | Never shared; specific to your PC. |

**Why .exe + .ps1 pairs?**
- The real work is written in Windows' own **PowerShell** (`.ps1`). So nothing extra has to be installed, and the files are plain text that anyone can read.
- The IDEs want an `.exe` as programmer. Each `.exe` is just a tiny launcher for the `.ps1` next to it.

## 3. Installation order

> Each step says what you should see. If you do not see it, go to section 10.

1. **Install Python.** Go to python.org → Downloads → Windows → "Windows installer (64-bit)". On the first screen, tick **"Add python.exe to PATH"**, then click Install Now.
   - Shortcut: `CNanoProg_Setup.bat -InstallPython` installs it with winget in step 6.
   - *You should see:* `python --version` in a new command window prints `Python 3.x.x`.
2. **Install the Positron compiler and your IDE.**
   - For VS Code: install it, then go to Extensions (Ctrl+Shift+X), find **"Positron"** (publisher *atomix*) and click Install.
   - *You should see:* a `.bas` compiles in the IDE and a `.hex` appears next to it.
3. **Unblock the zip, then extract it to `C:\CNanoKit`.**
   - Unblock: right-click the zip → **Properties** → tick **Unblock** → OK.
   - If "Windows protected your PC" (SmartScreen) appears: **More info → Run anyway**. This is normal for unsigned programs.
   - The setup writes this folder's path into the IDEs. If you move the folder later, run the setup again.
4. **Close all IDEs.**
5. **Plug in the kit** with no wires fitted.
   - *You should see:*
     - a **CURIOSITY** drive;
     - **"Curiosity Virtual COM Port (COMx)"** or **"USB Serial Device (COMx)"** under Device Manager → Ports;
     - the power LED on.
6. **Double-click `CNanoProg_Setup.bat`.** At the end you should see **ALL OK**. Lines marked **!!** tell you what to do:
   - "cannot write PositronStudio.ini" → right-click → **Run as administrator**;
   - "not on PATH yet" → run it once more;
   - "… is running" → close that IDE and run it again.
7. **Check:** `CNanoProg_Setup.bat -Check` reports the status and changes nothing.
8. **First test:** open `examples\CNANO_HELLO_56Q71.bas` in your IDE and program it (section 5). Then open **CNano Monitor** and press **Connect**.
   - *You should see:*
     - LED0 blinks;
     - `Hello/Merhaba 0 … 9` lines appear;
     - text you send comes back (echo);
     - pressing **SW0** prints `SW0`.

**What is the SW0 test for?** SW0 is the kit's small push button (RA0). The example program reports when it is pressed. This optional test only shows that the button input (RA0 with its internal pull-up) works; you can skip it.

## 5. Daily use with the three IDEs

Keep the kit plugged in. The program compares the PIC on the kit with your `Device =` line. If they differ, or the hex is damaged, it writes **nothing**.

### 5.1 Positron Studio
- **F10 = Compile and Program**, with "Curiosity Nano (CNanoProg)" preselected.
- Monitor: **Tools → CNano Monitor**.

### 5.2 Proton IDE
- **Program (CNanoProg)**, on the toolbar or under Plugin → "Curiosity Nano", compiles if needed, then programs the kit.
- **Monitor (CNanoMonitor)** opens the monitor.
- On the developer's Windows 11 PC, Proton IDE's own "Program" button did not start external programmers, so use the plugin buttons.
- Do not double-click `CNanoProtonPlugin.exe`; it only runs from inside Proton IDE.

### 5.3 VS Code (Positron extension)
- If the language box shows **"FBasic"**, switch it to **Positron**.
- With a `.bas` open, the **top-right corner of the editor** (right end of the tab row) has three icons: **Compile**, **Compile and Program**, **Program**. Hover to see their names.
- Keys: **Ctrl+Alt+M** = compile + program · **Ctrl+Alt+P** = program only · **Ctrl+Alt+C** = compile only (the Positron extension's own keys).
- The result appears in the **Output** panel.
- **Monitor:** **Ctrl+Alt+N**, or **Terminal → Run Task… → CNano Monitor** (the setup adds this VS Code user task).
- The icons only show while the file is in the **Positron** language. The setup adds `"files.associations": { "*.bas": "pos" }` to VS Code's settings for this. Still none? Click the language box at the bottom right → **Positron**, then restart VS Code once.
- **Ctrl+Alt+P does not compile** (seen 02 Oct 2026: the .hex of a changed .bas stayed old and CNanoProg warned "hex is older than the .bas"). If Ctrl+Alt+M does nothing: **Ctrl+Alt+C**, then **Ctrl+Alt+P**.

### 5.4 Command line
```
CNanoProg.exe "C:\work\BLINK.hex" 18F56Q71                 program + verify + reset
CNanoProg.exe "C:\work\BLINK.hex" 18F56Q71 -Mode dragdrop  by copying to the CURIOSITY drive
CNanoProg.exe -Mode info       kit, port, pack info (also what a double-click shows)
CNanoProg.exe -Mode reset | erase | read
-Lang tr | en
```

## 6. CNano Monitor

**It does not connect by itself.** The kit's port is preselected; you start the connection:

1. **Port**: the kit's port is listed first as "Curiosity …". If you plugged the kit in later, press **Scan ports**.
2. **Baud**: pick from the list or type a value from 1200 to 500000 (the limit of the kit's USB-serial bridge, DS50003481A §3.1.2.3). It must match your program.
3. **Data bits / Parity / Stop bits**: usually 8 / None / 1. The kit supports 8 data bits only; parity None/Odd/Even; 1 or 2 stop bits.
4. **DTR on**: **keep it ticked.** The kit passes no data without DTR (DS50003481A §3.1.2.4). The kit does not need RTS.
5. **Connect**: the settings lock and data starts. **Disconnect** stops it and unlocks the settings.

| Feature | Description |
|---|---|
| **Received data: Text / HEX / Text + HEX** | Text shows non-printable bytes as `<1B>`. HEX shows `48 65 6C`. Text + HEX shows each line with its bytes underneath. |
| **Send as: Text / HEX bytes** | Text sends your text plus the chosen line end (None/CR/LF/CR+LF). HEX accepts `55 AA 0D 0A`, `0x55,0xAA` or `55AA0D0A`, with no line end added. |
| Time stamp, Clear, Save… | Every session is also logged to `log\monitor_*.txt`. |
| **Reset PIC** | Restarts your program through the debugger. |
| **Quick send (4 buttons)** | Click = send. Defaults: `okmn`, `HEX:53`, `come`, `stop`. **Shift + click** = edit; a value starting with `HEX:` sends HEX bytes. |
| While the PIC keeps sending | Sending works at any time: type in the bottom box, press **Enter** or **Send**. |

**In your own program:** route UART2 to RB4 (TX) / RB5 (RX) with PPS. See `examples\CNANO_HELLO_56Q71.bas`: `RB4PPS = PPS_Fn_TX2`, `U2RXPPS = %00001101`.

## 7. Drivers, and "do I need MPLAB X?"

**No.** Seen on the developer's PC (Windows 11 Pro, MPLAB X installed):

| Kit USB function | Driver | Installed by |
|---|---|---|
| Debugger (CMSIS-DAP, HID), used for programming | Windows' own HID driver | **Windows** |
| CURIOSITY drive | Windows' own USB storage driver | **Windows** |
| Virtual COM port (CDC), used by the monitor | Microchip `atmel_debuggers_cdc.inf` (uses usbser.sys) | **MPLAB X setup** |
| "Curiosity Data Gateway" | Microchip WinUSB | MPLAB X setup; **not needed** |

- **Evidence:** DS50003481A §3.1.2.2 says *"On older Windows systems, the CDC requires a USB driver. The MPLAB X IDE installation includes this driver."*
- Windows 10/11's built-in `usbser.sys` binds to standard USB-CDC devices, so the COM port is **expected** to appear as "USB Serial Device (COMx)" without MPLAB X.
- **⚠ This is not yet tested on a clean PC.**
- **No COM port?** Install MPLAB X just for its driver; you never need to open it.

## 8. About Python

- **Why?** Microchip's official free tool **pymcuprog** runs on Python. Microchip states it supports "PIC devices mounted on Curiosity Nano kits".

- **Without Python?** Programming falls back to drag-and-drop, with limited verification. The monitor does not need Python.

## 9. (Optional) Jon Walker's FREELOADER bootloader

**First:** CNanoKit has **no link** to JonW's work.
- It contains none of his files or code, and it neither includes nor modifies FREELOADER.
- This section only explains how a user could try his free tool with this kit.
- Download FREELOADER from his protoncompiler.com forum thread, **under his licence terms**.

**Is a bootloader needed on this kit?** No. The kit's own programmer takes about 2 seconds. A bootloader makes sense for **your own board** with a serial port but no programmer. This kit is a good bench to try it on.

**Status (1 Oct 2026):**
- JonW's PIC18F56Q71 bootloader worked correctly on the real kit: sync, info, write, verify, exit and re-entry.
- **FREELOADER.exe 1.1 opens the kit's USB COM port with DTR off**, so the kit passes no data and the upload times out. This was reported to the author.
- So **today FREELOADER cannot be used through this kit's USB port.**

**Why two wires?**
- JonW's bootloader uses **UART1 on RC6 (TX) / RC7 (RX)**, but the kit's USB-serial line is on RB4/RB5. The two wires join them.
- Pictures: `docs\Wiring_FREELOADER_EN_01102026_2150.png` (EN), `docs\Kablo_Baglanti_TR_01102026_2150.png` (TR).
- Wire 1: **RC6 → RB4**, from left row hole 13 to left row hole 25.
- Wire 2: **RB5 → RC7**, from left row hole 26 to right row hole 28 (the bottom hole).
- Count holes from the top with USB up, and fit the wires with the kit unplugged.
- While the wires are fitted, your application must never make RC7 an output (RC7 = LED0, wired to the kit's CDC TX line) and must leave RC6 an input. The examples (HELLO, KOMUT) detect the RB5–RC7 wire at the first received byte and then never drive RC7. Remove the wires afterwards.
- A bootloader variant using the kit's own USB line (UART2 = RB4/RB5) would need no wires. This was passed to the author only as a suggestion.

**Once a FREELOADER that keeps DTR on is available:**
1. Write the bootloader once with the kit's programmer: `CNanoProg.exe P56Q71_MWBOOT.hex 18F56Q71`.
2. Compile your program **normally**. You do not add a bootloader to your code; FREELOADER places the application start itself.
   - Per the author's notes, your config must be compatible with the bootloader's, and the program must not reach the bootloader area at the top of memory.
   - See FREELOADER's own documents for details.
3. Upload: `CNanoProg.exe <app.hex> 18F56Q71 -Mode freeloader`. The kit's debugger does the reset.

**Note:** normal programming with CNanoProg (F10 / Ctrl+Alt+M) erases the chip, **including the bootloader**. To try again, repeat step 1.

## 10. Troubleshooting

| Symptom | Fix |
|---|---|
| "Kit not found" | Use a data cable and check that the CURIOSITY drive appears. Try another USB port. |
| PIC mismatch warning | The `Device =` line must match the kit (`18F56Q71`). |
| Plugin says it "does not run on its own" | It was double-clicked. Use the button inside Proton IDE. |
| Nothing in the monitor | Did you press Connect? Is DTR on? Do baud and format match your program? Does it use UART2 on RB4/RB5? Is any wire fitted on RB4/RB5? |
| No COM port | See section 7. |
| "Cannot open the port" | Close the other terminal program that has the port open. |
| F10 / Ctrl+Alt+M does nothing | Run the setup again with the IDE closed. |
| No buttons in Proton IDE | Close Proton IDE, run `CNanoProg_Setup.bat -Steps protonide`, then reopen it. |

## 11. Backup / new PC
- Back up `C:\CNanoKit` and your projects.
- On a new PC, repeat section 3 in order.

## 12. Uninstall
Delete:
- the shortcuts;
- `%APPDATA%\PDS\Plugin\CNano`;
- the Positron Studio programmer line, or restore the ini backup from `log\`;
- the `pos.main.programmer*` lines in VS Code's `settings.json`;
- the `C:\CNanoKit` folder.
